# Ghostline apps

One SwiftUI app target for iPhone and Mac (iOS 26 / macOS 26, Swift 6), generated by XcodeGen from `project.yml`,
plus the package `GhostlineKit` (API client, models, logic) that tests without a simulator.

## Build and test (on a Mac)

```bash
cd apple
~/tools/xcodegen/xcodegen/bin/xcodegen generate --spec project.yml     # or: xcodegen generate
swift test --package-path GhostlineKit
xcodebuild -project Ghostline.xcodeproj -scheme Ghostline \
  -destination 'platform=iOS Simulator,name=iPhone 17' CODE_SIGNING_ALLOWED=NO test
xcodebuild -project Ghostline.xcodeproj -scheme Ghostline \
  -destination 'platform=macOS' CODE_SIGNING_ALLOWED=NO test
# UI tests, iPhone only: the real screens tapped against fixed answers, no server and no sign-in
xcodebuild -project Ghostline.xcodeproj -scheme GhostlineUITests \
  -destination 'platform=iOS Simulator,name=iPhone 17' CODE_SIGNING_ALLOWED=NO test
```

The UI tests launch the app with `-uiTestScreen <name>` (watchlist, search, alert, order, trade, statement). In a Debug
build that opens one screen with the backend replaced by fixed answers (`Ghostline/Sources/UITestFixture.swift`); a
Release build does not contain that code. A new screen with a ticker field gets a case there and a test in
`GhostlineUITests/`.

Debug builds point at staging and Release builds at production (`Config/*.xcconfig` → Info.plist
`GHOSTLINE_API_BASE_URL`). Never hard-code an address.

## Release

`v*` tags run `.github/workflows/release.yml`: archive both destinations with the App Store Connect key from the
`testflight` environment and upload to TestFlight. `MARKETING_VERSION` is the repository's `VERSION`;
`CURRENT_PROJECT_VERSION` is the workflow run number.

## Design

Checked with the apple-design and liquid-glass skills: a tab bar on iPhone that becomes a sidebar on Mac, system
materials (`glassEffect`), the one allowed sign-in, every price with its source and time.
